# plan_GridView —— 上传默认可见 + 网格模式 + 缩略图

## 背景

两个问题，性质不同：

1. **上传看不见**。`-upload` 默认 false，直接跑 `trynet` 时服务端回
   `uploadEnabled: false`，前端什么都不画。就算加了参数，那个大虚线框也只在
   **空目录**时出现，有文件时只剩页头一个按钮，太隐蔽。
2. **网格模式没做**。之前排进队列，先做了分享链接，没回来补。

## 1. 上传：从"要记得加参数"改成默认可见

- `-upload` 默认改成 **true**，新增 `-read-only` 关掉它
- 环境变量 `TRYNET_READ_ONLY`
- **`-public` 下不自动开**，要显式 `-upload` 才写得进去

最后这条是刻意的不对称。默认有鉴权（随机密码），能写的人是拿到密码的人，
风险可控；`-public` 把门全开了，再默认可写就等于"公网上一个谁都能塞东西的目录"，
这不该是敲一行命令的副作用。两者同时显式打开时，banner 已经有警告。

### 界面

- 空目录：照旧是那个大拖放框
- **非空目录：列表底部常驻一条窄的虚线拖放条**，不再只靠页头按钮
- 整页拖放覆盖层照旧

## 2. 网格 / 列表切换

页头放两个图标按钮。选择存 `localStorage`，刷新后保持。

- **列表**（默认）：现在这套，一行一个文件
- **网格**：卡片，图片显示缩略图，其它显示放大的文件类型图标

`localStorage` 在隐私窗口和禁用站点数据时会抛异常，读写都包 try/catch，
取不到就回落到列表模式。

## 3. 缩略图

新路由 `/thumb/<path>`，内容过滤和 `/data` 共用，鉴权**只认会话 cookie**。

分享 token 在这里不收：拿到分享链接的人得到的是一个直接下载地址，从来不会
看到网格界面，给他开这条路只是白白多一个入口。

### 格式

**只支持 jpeg / png / gif**——标准库只认这三个。HEIC / WebP / AVIF 一律回退
到文件图标，不为了几个格式引第三方库。识别靠扩展名，解码失败也回退。

### 生成

解码 → 盒式降采样到最长边 160px → 编码成 JPEG（quality 80）输出。

降采样手写，约 25 行：目标每个像素对应源图一个矩形区域，把区域内像素求平均。
比 `image/draw` 的 NearestNeighbor 好看得多（缩小时最近邻会产生严重锯齿），
又不用引 `golang.org/x/image`。

### 上限

**源文件超过 12 MB 不生成缩略图**，直接回 404 让前端显示图标。

解码占的内存是按**像素数**算的，跟文件大小不成正比：一张 100 MP 的 PNG 压缩后
可能只有几 MB，解码成 RGBA 就是 400 MB。文件大小是个粗糙但够用的闸门，
真正的防线是它——这个进程可能同时在转发隧道流量，不能让一张图把它撑爆。

不做缓存。一个临时分享工具，重复请求同一张图的概率低，内存缓存的复杂度
换不回什么。浏览器那边的 `Cache-Control` 让它自己缓存。

### 懒加载

`<img loading="lazy">`，不自己写 IntersectionObserver。

**不做滚动分页**。`loading="lazy"` 已经解决了"几百张图一次性全下"这个实际
问题；条目本身的 DOM 开销要到几千个文件才显形。等真碰到再说。

## 4. 测试

上传默认：

- 不给参数时 `uploadEnabled` 为 true
- `-read-only` 时为 false，POST 上传被拒
- `-public` 单独给时**不**开上传
- `-public -upload` 同时给时开

缩略图：

- jpeg / png / gif 各自能出图，输出是合法 JPEG，最长边 = 160
- 非图片（.txt）→ 404
- 不认识的图片格式（.webp）→ 404
- 超过 12 MB → 404，且**没有解码过**（不能是"解码完了才发现太大"）
- 长宽比保持：横图、竖图、正方形各验一次
- 比 160 小的图不放大
- 鉴权：无凭据 → 401；会话 cookie → 200；分享 token → 401（`/thumb` 不收）
- 敏感文件名 → 404（内容过滤照样生效）

每条改完做变异验证：改坏实现，确认测试变红，再还原。

## 7. 执行记录

### 计划外的两处改动

**随机密码改成纯数字 8 位**（`passwordAlphabet` / `passwordDigits`）。
执行途中用户提的：密码经常是念给旁边的人、或在手机上敲，数字键盘一次到位；
长度保持 8 位，跟手机验证码一致。

我一度改成 10 位来补回熵（纯数字每位 3.3 bit，混合字符集是 5.8 bit），
用户明确要 8 位，按用户的定。8 位 ≈ 26.6 bit，对只活几十分钟的快速隧道
足够；长期挂着的固定域名用 `-pass` 指定自己的密码。
测试保留一条下限 `passwordDigits >= 8`，守住"别再往下掉"。

**目录列表多一个 `thumb` 布尔**。原方案是前端对每个条目都去请求 `/thumb`，
非图片靠 404 + `onerror` 回落。实测控制台每次渲染刷出一串 404——噪音是小事，
一个几百文件的目录白跑几百次请求是实的。改成服务端在列目录时就给答案。
服务端只看扩展名和大小、不解码，所以"扩展名对但内容坏"仍标 true，
由 404 和 `onerror` 兜底，这是刻意的。

### 修掉的界面 bug

页头加了 `.topbar-right` 容器却没给样式。`.topbar` 是 `space-between`，
右侧塞进第二个元素后两个控件各占一行，把切换按钮挤出了视口。

### 变异验证

改坏实现 → 确认测试变红 → 还原。共 18 条，全部变红。

头一轮有 5 条**仍然绿**，都是"通过的理由不对"，已重写：

- **宽度 clamp**：只测了横向极端（4000x3），`dw < 1` 那条 clamp 永远跑不到。
  补 `{3, 4000}`。
- **扩展名筛选**：靠"解码失败"兜底，测不出筛选本身。补一个内容是合法 PNG、
  名字叫 `.txt` 的文件。
- **`/thumb` 传 nil 不收分享 token**：token 绑的是 `/data/x`，请求是 `/thumb/x`，
  路径一比就对不上——两道保险指向同一结果，测试区分不了。已在注释里写明
  这条测的是结果，nil 留着是为了写明意图。
- **列表 `thumb` 标记的大小闸门**：复用超大图那条用例现成的 17 MB 夹具，
  不另造。
- （分享链接那一批的 3 条见 plan_ShareLink.md）
